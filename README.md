# OrderManagement-ERP
# ERP-система управления игровыми услугами (OrderManagement-ERP)

Бэкенд-система (REST API) для автоматизации, учета и распределения заказов на прокачку игровых аккаунтов. Проект спроектирован как полноценная CRM/ERP-платформа для управления бизнес-процессами в сфере игрового бустинга.

## Стек технологий
- **Платформа:** .NET 10.0 (ASP.NET Core Web API)
- **ORM:** Entity Framework Core
- **База данных:** PostgreSQL (Провайдер Npgsql)
- **Архитектура:** Многослойная архитектура (Layered Architecture) с паттерном DTO
- **Безопасность:** Идентификация пользователей и защита эндпоинтов на базе JWT-токенов (роли: Admin, Booster, Client)
- **Автоматизация:** Фоновые службы (.NET Hosted Services) для мониторинга зависших заказов и дедлайнов
- **Развертывание:** Контейнеризация с помощью Docker и Docker Compose

## Архитектура базы данных

### Таблица: Orders (Заказы)
- `Id` (Guid, PK) — Уникальный идентификатор заказа.
- `CreatedAt` (DateTime) — Дата и время публикации (UTC).
- `Status` (Enum) — Текущий статус заказа (`Created`, `InProgress`, `OnReview`, `Completed`, `Cancelled`).
- `TargetExperience` (Int) — Необходимый объем опыта для прокачки.
- `VehicleDetails` (String) — Техника или ветка развития (например, Т-80БВМ).
- `Deadline` (DateTime) — Крайний срок выполнения (дедлайн).
- `Price` (Decimal) — Стоимость заказа для клиента.
- `Payout` (Decimal) — Чистая выплата бустеру (исполнителю).
- `ClientId` (Guid, FK) — Идентификатор заказчика.
- `BoosterId` (Guid, FK, Nullable) — Идентификатор исполнителя (бустера).

### Таблица: Users (Пользователи)
- `Id` (Guid, PK) — Уникальный идентификатор пользователя.
- `Username` (String) — Никнейм (например, Discord-ник).
- `PasswordHash` (String) — Хэш пароля (безопасное хранение).
- `Role` (Enum) — Роль в системе (`Admin`, `Booster`, `Client`).
